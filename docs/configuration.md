# Configuration

The app keeps everything under its private files directory
(`Context.filesDir`, such as `/data/data/io.github.joelee.passalong/files`),
readable by the app only. There are no settings outside it.

| File | What it is |
|---|---|
| `config.toml` | The core's config, written by the setup screen in the format `passalong init` writes; every key is documented in [passalong's configuration doc](https://github.com/joelee/passalong/blob/main/docs/configuration.md) |
| `keys/id_ed25519`, `keys/id_ed25519.pub` | This device's identity for an SSH server, generated by the app; the public key goes into the server's `authorized_keys` |
| `api.key` | This device's API key for a passalong-server (`pal_<id>_<secret>`), readable by the app alone, as `init` keeps it beside the config; named in `server.https.api_key_file` |
| `list-cache.json` | The list cache, as `serve` keeps it on desktops |
| `Downloads/` | Staging for downloads: the core writes a verified file here, the app moves it to the device's Downloads and removes it |
| `.config/passalong/store.key` | Where the core would keep an encrypted store's key (`client.key_file`); not written yet, since joining an encrypted store is not implemented |

The core sees the files directory as `HOME`, so the paths the config
holds are the ones `passalong init` would write on a desktop, expanded
under the app's storage: `download_dir = "~/Downloads"`, the key file
beside a `.config/passalong/config.toml` that is not used, and `[serve]`
settings that only `serve` reads.

The setup screen fills the config from, for an SSH server:

| Field | Config key | Default |
|---|---|---|
| Server host name or address | `server.ssh.host` | |
| SSH port | `server.ssh.port` | `22` |
| User on the server | `server.ssh.user` | `passalong` |
| Storage directory on the server | `server.ssh.remote_path` | `/srv/passalong` |
| Name for this device | `client.device_name` | the device model, such as `Pixel-9` |
| (confirmed fingerprint) | `server.ssh.host_key` | fetched from the server |
| (generated) | `server.ssh.identity_file` | `keys/id_ed25519` in the files directory |

and for a passalong-server (`kind = "https"`):

| Field | Config key | Default |
|---|---|---|
| Server URL | `server.https.url` | |
| Name for this device | `client.device_name` | the device model |
| (confirmed pin, or none when the system is trusted) | `server.https.tls_pin` | fetched from the server |
| (typed or saved) | `server.https.api_key_file` | `api.key` in the files directory |

`serve.list_cache` and `serve.list_cache_check_secs` keep their defaults
(`true`, `60`), so the choose screen shows the cache while it was checked
within 2 minutes. Editing the file by hand needs a rooted device or
`adb shell run-as`; *Set up again* rewrites it.

## Secrets

The identity key has no passphrase and never leaves the files directory.
`PASSALONG_SSH_KEY_PASSPHRASE` is not read: the app hands the core an
environment with only `HOME` set. The API key is typed into a hidden
field, kept in memory only until the setup completes, then in `api.key`;
it never appears in the config, in logs, or in the list cache.

## Logging

The core's records go to logcat under the tag `passalong`, at level
`debug` in debug builds and `info` otherwise, in the core's format:

```text
2026-09-12T09:53:11Z info passalong_ffi::store items listed count=12
```

Clipboard text, file contents, keys, and secrets are never logged.
